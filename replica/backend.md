# Backend: tempt

Стек и роуты — `architecture.md`. Ключи в Vercel → Settings → Environment Variables. Список переменных — `.env.example`.

| переменная | откуда | статус |
| --- | --- | --- |
| ADMIN_PASSWORD | придумать | задан |
| BOT_TOKEN | @BotFather | задать (проверить) |
| CHAT_ID | ваш id / id чата заказов | задать (проверить) |
| PAYMENT_DETAILS | текст реквизитов | **не задан** |
| BLOB_READ_WRITE_TOKEN | создан при подключении Blob | задан автоматически |

После установки `BOT_TOKEN` нажать в `/admin` «Подключить бота» — это setWebhook с secret_token.

## Авторизация

- Один админ, пароль из env. Кука HttpOnly, SameSite=Strict, Secure на https, 7 дней, HMAC от пароля. Смена пароля разлогинивает все сессии.
- Регистрации покупателей нет и не нужно: заказ привязан к Telegram-нику.

## Данные

- Каталог: `products.json` в Blob, перезапись целиком. Резервная копия — скачивать файл из Vercel → Storage вручную, автобэкапов у Blob нет.
- Заказы: `orders/<ID>.json`, ID случайный 48 бит. Телефон и адрес не хранятся.
- Миграции не нужны. Новые поля (`soldOut`, `color`) опциональны, старые записи читаются как есть.

## Платежи

Нет на сайте: реквизиты присылает бот, сверка оплаты вручную по скриншоту в чате. Stripe не применим (РФ).

## Интеграции

- **Telegram Bot API.** Webhook проверяется заголовком `X-Telegram-Bot-Api-Secret-Token`. Всегда отвечает 200, поэтому повторов нет. Бот пишет только тем, кто нажал Start.
- **СДЭК / Яндекс Доставка** — нет договора и ключей, выбор ПВЗ вручную. **Ozon** — публичного API нет.

## Безопасность

- [x] Секреты только в env, `.env` в `.gitignore`, в клиентском коде секретов нет.
- [x] Ввод проверяется на сервере на каждом роуте: длины, формат ника и телефона, цены и размеры пересчитываются по каталогу, согласие на ПД, «нет в наличии».
- [x] Авторизация на каждой записи. Без куки `/api/products` POST/PUT/DELETE, `/api/upload` и `/api/tg-setup` отвечают 401 (проверено).
- [x] Лимиты: вход — 10 за 15 мин, заказ — 5 за 10 мин с IP. В памяти инстанса, поэтому слабые. При спаме — Vercel Firewall.
- [x] Вебхук проверяет secret_token.
- [x] Загрузки: только jpeg/png/webp/avif, ≤4 МБ, отдаются с отдельного домена Blob.
- [x] Персональные данные не попадают в URL и логи. В логах только тексты ошибок.
- [x] `npm audit --omit=dev`: 0 уязвимостей.
- [x] Политика конфиденциальности называет Vercel и Telegram.

## Риски, которые закрывает не код

- **152-ФЗ, локализация.** Первичный сбор ПД граждан РФ должен идти в базы на территории РФ. Сейчас имя и ник лежат в Blob (Германия), полные данные заказа уходят в Telegram. Для полной законности: хранить заказы на российском хостинге или не хранить ПД вовсе, и подать уведомление в Роскомнадзор как оператор ПД. Это вопрос к юристу.
- **Реквизиты оператора** в `privacy.html` — заглушки, их нужно заполнить.

## Изменение 2026-10-19

Бот для клиентов убран по решению владельца: нет вебхука, `/status`, `/msg`, хранения заказов `orders/*` и `PAYMENT_DETAILS`. Бот только присылает владельцу сообщение о новом заказе (`BOT_TOKEN`, `CHAT_ID`). С клиентом владелец связывается сам по нику из заказа. ПД на сайте больше не хранятся.
